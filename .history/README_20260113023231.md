## Financial Data Analysis Project

It has Financial Data Pipeline: API → MySQL → Analysis

## Executive Summary

This project delivers an **end-to-end financial data pipeline** that automatically collects market data from external APIs, stores it securely in a **MySQL database**, transforms it into analysis-ready formats, and produces **insightful analytics and reports**.

Think of it as a **data highway**: raw market data comes in, gets cleaned and structured, and exits as decision-ready insights. The solution is modular, scalable, and designed with both **technical teams and business stakeholders** in mind.

## Business Problem Addressed

Financial data is often:

* Scattered across APIs
* Hard to store consistently
* Difficult to analyze without manual effort

This project solves that by:

* Automating data ingestion
* Centralizing storage in SQL
* Enabling reproducible analysis
* Supporting future dashboards and AI-driven insights

## High-Level Architecture

1. **Data Source (API)** – Market data from yfinance(a python library which contains stocks / financial indicators) and store in the form of json
2. **Ingestion Layer** – Python scripts fetch from database and validate data
3. **Database Layer** – MySQL stores structured, queryable data
4. **Transformation Layer** – JSON → CSV → analytics-ready tables
5. **Analytics Layer** – SQL + Python analysis (EDA, metrics) with the help seaborn and matplotlib
6. **Reporting Layer** –  PDF Report, Jupyter notebooks and insights in the form of graph and bar chart etc

### What each layer does (in simple terms)

* **data/** → Stores raw and cleaned datasets
* **database/** → Defines how financial data is structured in MySQL
* **notebook/** → Used by analysts to explore trends & patterns
* **src/** → Automation engine (API calls, DB operations, transformations)
* **reports/** → Business-facing outputs and final report

## Key Components

### 1. Database Schema (schema.sql)

*Defines structured tables for storing financial market data
*Specifies data types, primary keys, and constraints
*Ensures data integrity and consistency for time-series analysis

**Business value:** Provides a reliable and scalable data, enabling efficient querying

### 2. API to MySQL (`api_to_mysql.py`)

* Fetches financial data from external APIs
* Cleans and validates responses
* Inserts data into MySQL tables

**Business value:** Eliminates manual data collection

### 3. Database Configuration (`config.py`)

* Centralized configuration for:

  * Database credentials
  * API keys (if required)

**Business value:** Secure, maintainable configuration management

### 4. Fetch from MySQL (`fetch_from_mysql.py`)

* Runs SQL queries
* Extracts stored financial data
* Sends data downstream for analysis

**Business value:** Enables repeatable, auditable analytics

### 5. JSON to CSV (`json_to_csv.py`)

* Converts raw API JSON into structured CSV
* Prepares data for BI tools, Excel, or ML models

**Business value:** Makes data universally consumable

### 6. Exploratory Data Analysis (`eda.ipynb`)

* Identifies trends, volatility, and performance metrics
* Combines SQL + Python analytics

**Business value:** Turns data into insights

### 7. AI Investment Summary Engine (ai_summary.py)

* Classifies assets based on annualized volatility (risk) and CAGR (growth)
*Generates rule-based, explainable investment summaries
*Optionally enhances summaries using a local LLM (Ollama) for professional language
*Includes safe fallback to deterministic logic if AI enhancement fails
*Outputs investor-ready insights in CSV format

**Business value:** Transforms complex financial metrics into clear, actionable insights to make informed investment decisions without deep market expertise.
